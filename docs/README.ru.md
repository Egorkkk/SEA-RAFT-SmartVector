# SEA-RAFT SmartVector для Nuke

Плагин вычисляет оптический поток моделью SEA-RAFT и записывает в EXR слои SmartVector, пригодные для штатной ноды `VectorDistort`. Вычисление идёт в отдельном Python-процессе на NVIDIA GPU; Nuke управляет подготовкой кадров и финальным рендером. Поддерживается Windows без WSL и виртуальной машины Linux.

## Что понадобится

- Nuke 17: на этой версии проверены создание ноды и двухкадровый рендер. Другие версии Nuke пока не проверены.
- 64-битная Windows, NVIDIA GPU с поддержкой CUDA и драйвер для CUDA 12.1 (не ниже 527.41).
- Git for Windows, PowerShell, доступ в интернет при первой установке.
- Место для Python, PyTorch и весов модели, а также для рабочих EXR. Установка загружает несколько гигабайт данных. Для длинных кадровых последовательностей учитывайте объём RGB EXR и 28 каналов векторов.

## Установка

1. Скачайте архив `SEA-RAFT-SmartVector-v0.1.0.zip` из [релиза](https://github.com/Egorkkk/SEA-RAFT-SmartVector/releases) и распакуйте в постоянную папку. После установки не перемещайте эту папку: Nuke ссылается на неё по абсолютному пути.
2. Откройте PowerShell в распакованной папке и выполните:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\install_windows.ps1
   ```

3. Дождитесь сообщения `Installed`. Установщик скачает SEA-RAFT, Python 3.10, PyTorch, OpenEXR и модель, проверит CUDA и добавит путь плагина в `%USERPROFILE%\.nuke\init.py`.
4. Перезапустите Nuke. В меню Nodes должен появиться пункт **SEA-RAFT → SEA-RAFT SmartVector**.

Проверить план без установки: `powershell -File .\scripts\install_windows.ps1 -Plan`. Для среды на другом диске: `-RuntimeDirectory D:\NukeAIRuntime`. Повторный запуск установщика использует уже скачанные компоненты.

## Первый рендер

1. Подключите изображение к **SEA-RAFT SmartVector**. Для диапазона **Input** подключайте `Read` непосредственно к ноде; при другой схеме диапазон берётся из настроек проекта. Можно задать **Custom**.
2. Нажмите **Export Write** на вкладке **SEA-RAFT SmartVector**. В основном графе появится подключённая `Write`.
3. Укажите на `Write` путь к EXR-последовательности, например `D:/shot/vectors/smartvector.####.exr`.
4. Нажмите **Generate + Render** на самой ноде **SEA-RAFT SmartVector**, сразу под **Export Write**. Нода подготовит входные кадры, вычислит поток и запустит `Write`.
5. Проверьте итоговый EXR в Nuke: он должен содержать исходные каналы и слои `smartvector_f01_v01` … `smartvector_f64_v01` с каналами `p_u`, `p_v`, `n_u`, `n_v`. Проверьте результат на коротком движущемся фрагменте через штатный `VectorDistort` до рендера всей сцены.

Итоговый `Write` настроен на `all` channels и 32-bit float EXR. Обычная кнопка Render у `Write` выводит уже подготовленные векторы; она не запускает SEA-RAFT. После изменения входных изображений или параметров снова используйте **Generate + Render**. При изменении уже рассчитанных кадров включите **Advanced → Overwrite Existing**; в противном случае плагин остановится, чтобы не смешать разные результаты.

## Рабочие файлы и повторный запуск

По умолчанию рядом с выходным EXR создаётся `.sea_raft_work/<id>`. В ней находятся исходные RGB EXR, векторные EXR, `job.json` и `smartvectors.json`. Внутренняя `Read` ноды использует векторные файлы при просмотре и после повторного открытия скрипта. Сохраняйте эту папку вместе с проектом, пока нода нужна в графе; она не является системным кэшем Nuke. Путь можно переопределить через **Advanced → Working Directory** до генерации.

Прерванную генерацию можно запустить повторно. Готовые кадры будут использованы повторно, если вход и настройки совпадают. Для принудительного пересчёта включите **Overwrite Existing**. После завершения проекта рабочие файлы можно удалить вручную, если в графе больше не нужны векторные слои; итоговые EXR от `Write` при этом сохранятся.

Настройка **Max Dimension** ограничивает разрешение входа модели; `0` означает полное разрешение. **Temporal Levels** определяет шаги кадров, для которых создаются векторы. При нехватке видеопамяти уменьшите **Max Dimension** или число уровней. Непрозрачность, матовые области и поведение штатного SmartVector не воспроизводятся автоматически: проверяйте пригодность потока на конкретном материале.

## Обновление и диагностика

- После обновления файлов перезапустите Nuke и откройте скрипт заново. Старые ноды обновляются при открытии; для уже открытого скрипта используйте **SEA-RAFT → Upgrade Existing Nodes**.
- Если не видно **Generate + Render**, проверьте вкладку **SEA-RAFT SmartVector** самой ноды и обновление скрипта. Кнопка расположена сразу под **Export Write**.
- Если кнопка **Export Write** не создаёт `Write`, подключите входное изображение и проверьте статус ноды. `Write` должна появиться в основном графе, ниже SmartVector.
- Если рендер сообщает о смене настроек кэша, включите **Overwrite Existing** либо выберите другой путь `Write`/рабочей папки.
- Если ошибка связана с CUDA, запустите установщик повторно: он проверяет GPU, модель и OpenEXR. Проверьте, что путь **Advanced → SEA-RAFT Python** у ноды указывает на установленную среду.
- Если итоговая EXR-последовательность есть, но просмотр через ноду перестал показывать векторы, проверьте наличие `.sea_raft_work/<id>` и нажмите **Advanced → Refresh Status**.

Для пакетного рендера или рендер-фермы недостаточно отправить только `Write`: сначала нужны подготовленные рабочие векторы и доступ к ним с машины рендера. Автоматическая установка на ферме и проверка цветового конвейера пока не входят в этот релиз.

## Что проверено

Установка и полный рендер двух кадров проверены на Windows, Nuke 17 и NVIDIA RTX 4060 Ti. Тест проверяет создание `Write`, запуск обеих кнопок, сохранение EXR, 32-bit float, размер кадра и наличие всех 28 векторных каналов. Проверка качества оптического потока на производственном материале остаётся задачей конкретного проекта.

После установки можно дополнительно проверить направление потока на контрольном сдвиге изображения на четыре пикселя:

```powershell
$env:PYTHONPATH = (Get-Location).Path
& .\.runtime\venv\Scripts\python.exe tests\verify_motion.py
```

Проверка ожидает около `+4` в канале `n_u` первого кадра и `−4` в `p_u` второго кадра.
